# Проверка issues и olcrtc, 7 сентября 2026

Проверены 20 открытых issues `alananisimov/olcbox` и актуальность жалоб относительно ядра. Переводы и прочие вкусовые пожелания не реализовывались.

## Изменения

- Переключение Android/iOS: отмена старой попытки сразу, ожидание готовности порциями до 200 мс, отдельный Runtime для следующего подключения. Завершение предыдущей сессии не держит интерфейс. Пауза Jitsi применяется только при повторном входе в ту же комнату.
- Подписки: сетевые запросы больше не держат блокировку хранилища. Выбор локации и удаление подписки работают во время зависшего обновления. Ответ не воскрешает удалённую подписку. Существующая выбранная локация сохраняется после refresh; новые записи не забирают её storage ID.
- #142: повторная установка уже скачанного APK доступна через Check now → Install. Кэш проверяет идентичность релиза и размер; незавершённые и отменённые загрузки не становятся установочными файлами.
- #149: восстановлен мост логов Android/iOS. Для этого перенесён уже существовавший локальный commit olcrtc `22a8190` на актуальный upstream. Логи вспомогательных проверок и старых сессий не используются как команда перезапуска активного VPN. Пароль SOCKS больше не выводится в стартовый журнал.
- #152: iOS больше не обрывает каждое подключение через 8 секунд. Общий бюджет 60 секунд можно отменить при остановке или выборе другой локации.
- #154: добавлены Leanback launcher, необязательный touchscreen и banner. Это доступность в лаунчере TV, не полный аудит управления пультом.
- Сохранены и проверены уже лежавшие в рабочей папке изменения #125: ручное обновление на главной, description/comment и индикатор квоты.
- CI: PR и release читают один SHA из `.github/olcrtc-revision`; выпуск зависит от тестов ядра с `-race`. Native Gradle tasks учитывают исходники `pkg`, desktop tasks отслеживают исходники ядра; исправлена конфигурационная кэшируемость iOS task.

## Ядро

Закреплён `alananisimov/olcrtc@08843d6accd7f43a1d04aa0ac7a3d5ea90e27efa`: upstream `189d16c` плюс существовавший мобильный LogWriter. Ветка `fix/olcbox-mobile-logging` доступна в форке, основной upstream и локальная старая ветка не изменены.

Из upstream взяты исправления Jitsi EndpointMessage (`14fac07`), reconnect race (`65ed59e`), VP8/KCP single-write (`3dd8c45`) и обработки Goolom SDP. Собственных изменений wire protocol нет. Пробное уменьшение размера Jitsi-пакетов не устранило ошибку и не включено в итоговый код.

**Нерешённая проблема:** длительная передача Jitsi/DataChannel через `meet.ffmuc.net` и `meet.riddlerx.org` приводит к несовпадению проверочного потока. Диагностика показала пропуски номеров аутентифицированных записей. Ошибка воспроизводится и на старом релизном `f616f57` (пример: mismatch на 1 675 264 байтах), и на текущем ядре (пример: 6 770 688 байт на riddlerx). Поэтому успешный handshake или сборка не являются доказательством надёжности Jitsi под нагрузкой. Это воспроизведение отдельного Go client/server без Olcbox; #139/#153 нельзя считать полностью исправленными клиентом.

## Воспроизведение Jitsi вне клиента

```sh

  -run '^TestRealThroughputSoak$' \
  -olcrtc.real-e2e -olcrtc.real-soak \
  -olcrtc.real-soak-provider=jitsi \
  -olcrtc.real-soak-transport=datachannel \
  -olcrtc.real-jitsi-room=https://meet.riddlerx.org/UNIQUE_TEST_ROOM \
  -olcrtc.real-soak-duration=45s -timeout=4m
```
